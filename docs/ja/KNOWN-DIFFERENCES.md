# GNU sed 4.9 との既知の差分

ripgsed は GNU sed 4.9 と完全に同じ動作（同じ出力、C ロケールでの同じエラーメッセージ、同じ終了状態）を目指しています（[DECISIONS.md](DECISIONS.md) の D4）。このページは、そうなっていない点と、バグのように見えても glibc の挙動をそのまま真似ている点を挙げます。

## 意図的な差分

- `--version` と `--help` は ripgsed 独自の文面を出します。usage の先頭行とオプションエラーの `sed:` の行は GNU sed と同じです。
- 実装しているロケールは `C` と UTF-8 のみです。その他のマルチバイトエンコーディングはバイト列として読みます。
- メモリ使用量は多めです。入力を 256 KiB のブロック単位で読み、並列実行では複数のブロックを同時に保持します。

## 再現している glibc の挙動

GNU sed は C ライブラリの正規表現マッチャーを使っています。そのマッチャーが仕様にない動きをする場合、スクリプトが同じ出力になるよう ripgsed も同じ動きをします。

- パターンが1文字の繰り返し（`b*`、`[ab]*`、`(a*)*`、`a*\+`）で始まり、その直後に `\B` がある場合、その位置で繰り返しが1文字を消費できるときの空マッチは、その文字の後ろで報告されます。`echo ab | sed 's/b*\B/<&>/'` は `a<>b` ではなく `ab<>` を出力します。バッファの先頭では起きず、`\b`、`\<`、`\>` にも当てはまりません。fixture は `rgx-039` です。
- 繰り返しの中にあるグループへの後方参照は、POSIX が許す値のすべてを見るわけではありません。上限のある繰り返し `X{m,n}`（`?` は `{0,1}` で、`+`、`*`、`{m,}` は上限なしです）はグループのコピーに展開され、グループが見えるのは `m` 回か `n` 回の繰り返しの後だけです。`echo aaa | sed -E 's/(a){1,3}\1/<&>/'` は `<aaa>` ではなく `<aa>a` を出力します。さらに、あるコピーの値は、同じグループの別のコピーも同じ位置で終われるとき、見えません。ただし、その別のコピーが、より前のコピーで開始が同じか早いもの、またはより後ろのコピーで開始が遅いものである場合です。`aaaa` に対する `(a+)+\1` は `aa` にしか一致せず、`(a|aa){2}\1` は `aaa` に一致しませんが `aaaa` には一致し、`(a*){2}\1` はどこにも一致しません。例外が2つあります。グループの本体が空になれない場合、繰り返しの任意のコピーの中にあるコピーは、開始が同じ必須のコピーに妨げられません。本体が空になれる場合、必須のコピーは、後ろの任意のコピーに妨げられません。コピーがどこから始まりうるかは、マッチの先頭からパターンを後方参照を見ずにたどって求めます。対象は長さ 256 バイトまでのマッチと、コピーが 16 個までのグループです。fixture は `rgx-040` です。
- UTF-8 ロケールの文字クラス（`[[:alpha:]]`、`\w` など）は glibc の `C.utf8` の表に従います。表は C ライブラリから生成しており（`tools/gen-classes.py`）、Rust の標準ライブラリではなく glibc の Unicode バージョンに従います。

## 再現していない glibc の挙動

glibc のマッチャーが、最左最長の規則や後方参照の定義と食い違う結果を返す場合です。差分テスト（`tests/regex_differential.rs`）のランダムなパターンの約 0.1% が該当しますが、通常のパターンでは起きません。ripgsed は定義どおりの結果を返します。

| パターン（ERE）   | 入力      | glibc                   | ripgsed              |
|-------------|---------|-------------------------|----------------------|
| `(a*)*\1b`  | `ab`    | `ab` に一致                | `b` に一致（オフセット 1 から）  |
| `a?(a+)+\1` | `aaaaa` | `aaaaa` に一致、`\1` は `aa` | `aaa` に一致、`\1` は `a` |
| `(a?){2}\1` | `baaa`  | 一致なし                    | `aaa` に一致            |
| `(a?)*\1`   | `a`     | `a` に一致、`\1` は `a`      | 空の一致                 |

4つとも、繰り返しの中にあるグループへの後方参照で、グループまたは繰り返しより前の部分が空になれたり幅が変わったりするため、上の2つの規則では足りないものです。固定幅のグループ（`(ab)+\1`）は仕様どおりに動きます。重ねた量指定子の下のキャプチャ（`((b?)+*|c){1}`）や、パターンの先頭でない繰り返しの後ろの `\B` でも差が出ることがあります。一覧上の項目は `compat/sed.tsv` の RGX-009 と RGX-012、保留中の fixture は `rgx-012-backref-group-in-star-iteration` です。

## glibc への報告

上の後方参照と `\B` の例は、sed を使わず素の `regcomp`/`regexec`（`REG_EXTENDED`）でも再現します。

```c
regcomp(&re, "(a+)+\\1", REG_EXTENDED);   /* "aaaa": reports [0,2), the longest is [0,4) */
regcomp(&re, "(a*){2}\\1", REG_EXTENDED); /* "aaaaaa": no match, [0,6) is one */
regcomp(&re, "b*\\B", REG_EXTENDED);      /* "ab": reports the empty match at 2, not at 1 */
```

glibc 2.43（Ubuntu 2.43-2ubuntu2.4）で確認しました。glibc のバグトラッカー（コンポーネント `regex`）への報告では、POSIX が最左最長のマッチを求めていること、`\B` はマッチの位置で成り立たなければならないことを書きます。
