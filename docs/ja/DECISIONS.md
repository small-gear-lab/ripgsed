# 決定事項

これまでに決めたことと、その理由です。提案と未決の事項は [DESIGN.md](DESIGN.md) に置きます。決定は見直せますが、黙って消さずに、変更をここに記録します。

## D1. ライセンス：`MIT OR Apache-2.0`

- このプロジェクトは独立実装で、Rust のエコシステムで一般的なデュアルライセンスの `MIT OR Apache-2.0` でライセンスします。
- GPL のコードに由来するものは追加しません。GNU sed と GNU grep は参照としてだけ読み、コピーしません（DESIGN.md の由来の方針を参照）。

## D2. 入力表現：バイト列

- 入力、pattern space、hold space、出力は `String` ではなくバイト列です。GNU sed との完全互換には、不正な UTF-8 と NUL を受け付ける必要があります。
- レコード末尾の区切り（LF または NUL）は、レコード本文と別に保持します。最終改行がないことは保持し、正規化しません。
- P0 の対象は `C` ロケールのみで、`LC_ALL=C` の GNU sed と一致するバイト単位の挙動です。マルチバイトの文字単位の挙動（たとえば `.` が 1 文字にマッチする）は後の段階であり、それまでは達成したと主張しません。
- 入力はバッファ付きのストリームで読みます。メモリはファイル全体のサイズではなく、単一レコードの長さに応じて増えます。

## D3. 正規表現はエンジンの抽象化の裏に置く

- コアは正規表現ライブラリを直接呼びません。エンジンのインターフェース（DESIGN.md の「エンジンの抽象化」を参照）を使うので、このプロジェクト自身のエンジン（D7）と、opt-in の拡張としての PCRE2 などのエンジンを、並べて置けます。
- エンジンは（構文方言とオプションにより）明示的に選び、未対応の構文があっても黙って切り替えません。

## D4. GNU sed の完全互換は最低要件

- GNU sed と完全に互換になるまで、ripgsed は `sed` の代替としてリリースも説明もしません。完全互換とは、有効な GNU sed の呼び出しのどれに対しても、同じ stdout、終了状態、ファイルへの影響を返すことです。意図的に異なるのは、バージョン表記とヘルプの文面だけです（DESIGN.md を参照）。
- P0 のようなマイルストーンは作業の順序であり、小さな製品ではありません。この要件に関して、部分集合を「完了」と見なすことはありません。
- したがって範囲は、GNU sed のマニュアルにあるすべてです。すべてのコマンド、オプション、フラグ、エスケープ、アドレス形式、特殊なケースを含みます。互換性の一覧は最初からそれらをすべて挙げ、それぞれを未対応・部分対応・検証済みのいずれかとして記録し、未対応のものはコンパイル時エラーにします。
- 範囲には、マルチバイトと UTF-8 ロケールの挙動（D2 は作業の順序を決めただけで、まず `C` ロケール）と、`--debug` が明示的に含まれます。`--debug` の正規形のプログラム表示と実行の注釈も、ほかの出力と同様に GNU sed と比較します。
- 互換性は、GNU sed との差分テスト（リポジトリの tests/README.md を参照）でのみ検証し、主張だけで済ませることはありません。
- grep モードは、sed モードの後に、GNU grep について同じ水準を目指します。

## D5. 終了状態とエラーメッセージは GNU sed と完全に一致させる

- 終了状態は、文書化された 0・1・2・4 や `q`・`Q` に与えるコードを含め、すべての場合で GNU sed と同一です。
- stderr に出すエラーと警告のメッセージは、`C` ロケールの GNU sed のメッセージと一字一句同一です。`-e expression #1, char 3:` のような位置の部分も含みます。
- 呼ばれた名前に従うのはプログラム名の接頭辞だけです。`sed` として実行すれば `sed:`、`ripgsed` として実行すれば `ripgsed:` になります。これは名乗り方を意図的に変えたことの帰結であり、互換性の例外ではありません。
- gettext で他の言語に翻訳されたメッセージは、互換性の一覧のロケールの項目に属し、英語のメッセージの後に対応します。
- 差分テストは、stdout と終了状態に加えて stderr も比較します。

## D6. 互換の基準：GNU sed 4.9

- 挙動と、生成するテストの期待値の基準は、執筆時点で最新の安定版である GNU sed 4.9 です。
- 新しい GNU sed で変わった挙動は、黙って追従しません。互換性の一覧に別項目として記録し、基準のバージョンは改めて決めます。
- `--version` が出力するバージョン行には、この基準を明記します（DESIGN.md を参照）。

## D7. 正規表現エンジンは自前で書く

- つなぎとしても、サードパーティの正規表現ライブラリは使いません。POSIX の左端最長一致、後方参照、GNU 拡張を備えた GNU sed の BRE と ERE を、最初のリリースからこのプロジェクト自身のエンジンで実装します。
- 方言には、既定の GNU の挙動だけでなく、BRE と ERE の `--posix` と `POSIXLY_CORRECT` の変種、およびロケールが含まれます（D2 は作業の順序を決めたもので、まず `C` ロケール、その後に UTF-8 などのマルチバイトロケール）。
- 仕様は、GNU sed 4.9（D6）の観測できる挙動であり、POSIX と異なる箇所も含みます。その挙動は、GNU sed との差分テストが決めます。
- エンジンは D3 のインターフェースの裏にあるので、単独でテスト、ベンチマーク、ほかのエンジンとの比較ができます。
