# grep モード

ripgsed は GNU grep としても振る舞います。モードはプログラムが実行される名前で選ぶので、`ln -s ripgsed grep` だけで足ります。`grep`、`egrep`、`fgrep`、`rgrep` が grep モードで動き、最初の引数 `--grep` を付ければ、元の名前のままでも同じになります（`ripgsed --grep -n pattern file`）。メッセージには、GNU grep と同じく `grep` という名前が付きます。

目標は sed モードと同じです（[DECISIONS.md](DECISIONS.md) の D4）。C ロケールでも C ライブラリのロケールでも、同じ出力、標準エラーの同じメッセージ、同じ終了状態を返します。grep モードの規則は D12 に記録しています。

## GNU grep と何を比べているか

- `compat/grep.tsv` は、挙動を領域ごとに挙げます。起動、パターン、出力、文脈、ファイル、バイナリファイル、色、`-P` です。83 項目すべてが `verified` で、それを覆う fixture が、GNU grep と同じ標準出力、標準エラー、終了状態、ファイルを返すという意味です（`tests/README.md`）。grep モードの fixture は 89 個あり（`tests/fixtures/grep-*` と `pcre-*`）、`tools/gen-grep-fixtures.py` が書き、`tools/gen-fixtures.sh` がそのマシンの grep の出力を記録します。
- 基準は、期待結果を作るマシンの GNU grep です（D12）。その版と PCRE2 の版は `tests/reference-grep.json` にあり、CI の `fixtures` ジョブもこれを調べます。ランナーが別の版を持ち込めば、ジョブがそれを知らせます。GNU grep 3.11（Ubuntu 24.04 のリリース）と 3.12 は、試したすべての場合で同じ結果を返します。ただし `-u` と `--unix-byte-offsets` は 3.12 でなくなっていて（ripgsed は 3.12 に従います）、PCRE2 のメッセージは版によって違います。`tools/ref-grep.sh` は別のリリースを取り出して（署名つきのアーカイブ索引でハッシュを確かめます）、版が何を変えるかを見られるようにします。
- 細部の多くは、`cargo test` に含まれないランダムテストが見つけました。ランダムなパターン（基本、拡張、固定。`-i` `-w` `-x` `-v` つき、C ロケールと UTF-8 ロケール）と、サンプルファイルへのランダムなオプションの組み合わせを、両方のプログラムで実行し、出力、メッセージ、終了状態を比べます。数千件ずつの直近の実行で、食い違うのは 500 件に 1 件ほどで、それは `docs/KNOWN-DIFFERENCES.md` の場合です。

## パターン

GNU grep はパターンを 2 度読みます。自前の DFA（gnulib のもの）がどの行が一致するかを決め、C ライブラリの正規表現マッチャ（GNU sed が持つもの）が、`-o` と `--color` のための一致を見つけ、DFA に決められないときは行も決めます。ふつうに書かれるパターンでは両者は一致し、変わったパターンで食い違います。式の先頭、アンカーや単語アサーションの後にある繰り返し演算子、正しくない範囲指定などです。ripgsed は、そのようなパターンの両方の読み方を持ちます。行は DFA の読み方で選び、一致は C ライブラリの読み方から得ます。GNU grep の DFA が降りる場面では、C ライブラリの読み方が行も選びます。後方参照のあるパターンと、マルチバイトのロケールでクラス、否定集合、`\w`、単語アサーションのあるパターンです。パターンの間違いは、C ライブラリのメッセージになります。GNU grep はまずそれでコンパイルするからで、DFA のメッセージ（`invalid content of \{\}`）は 2 番目です。

構文は GNU grep のもの（`RE_SYNTAX_GREP`、`RE_SYNTAX_EGREP`）で、GNU sed のものではありません。

- ERE の式の先頭にある繰り返し演算子（`*a`、`+a`、`{1}a`、`(` や `|` の後）は、警告つきで読み飛ばされます（`grep: warning: * at start of expression`）。不正な範囲指定（`a{1`、`a{x}`）と、対応のない `)` は文字です。間違いになるのは `{2,1}` と、32767 を超える数だけです。
- BRE の先頭の `*` は文字で、先頭の `\{` は文字 `{` です。演算子が 2 つ続くこと（`a**`、`a\{1\}\{2\}`）も許されます。
- sed のエスケープ（`\n`、`\t`、`\a`、`\x41`）はありません。普通の文字の前のバックスラッシュは、その文字そのものです。`-i` の下では、C ライブラリは、特別な意味のないエスケープされた文字を、大文字にした文章と比べるので、そこでは決して一致しません。行を選ぶのは DFA で、DFA にはこの間違いがありません。
- `-w` と `-x` は、DFA に対しては、パターンを包んだもの（`(?<!\w)(?:` と `)(?!\w)`、または行全体）です。`-o` と `--color` の一致は素のパターンのもので、GNU grep が調べるとおりに調べます。いちばん左の一致が単語か、同じ位置のもっと短い一致か、もっと先の一致を試します。短い一致は、GNU grep が、検索を始めた位置から測った場所で切り落とした文章の中から探すので、行の先頭から測るのではありません。そのため `echo 'x y z' | grep -ow '[^a] *'` は `x` と `z` を出して `y` を出さず、ripgsed も同じです。`-w` と `-x` の両方を指定したときは、行末に届く一致を、改行つきの行の残りとして報告します。
- 複数のパターン（`-e`、`-f`、改行）は別々の正規表現です。`-o` の一致は、そのうちいちばん左の、同じ位置ならいちばん長いものです。
- `-F` は、特別な文字をすべてエスケープして書いたパターンです。`-i` とクラスは、sed モードと同じくロケールに従います。

## 入力の読み方

- 入力は来たとおりに読みます。パイプは書かれている最中に検索でき（`tail -f log | grep --line-buffered x` が動きます）、大きなファイルがメモリに収まる必要もありません。早く見つかった一致で読むのを終えます（`-m`、`-l`、`-q`）。
- GNU grep は塊ごとに読み、塊ごとに、そのデータがバイナリか（NUL バイトがあるか）を決めます。通常のファイルは、決まった位置で 96 KiB の塊として読むので、最初の NUL より前の塊の行は文字として出力され、その塊以降で終わる行は出力されません（そこで何かが選ばれていれば、標準エラーに `binary file matches` が続きます）。パイプの塊は、そのときの読み込みです。ripgsed も同じようにし、ファイルでは同じ位置を使います。パイプでは、GNU grep と同じく、読み込みの大きさが決めます。
- UTF-8 のロケールでは、エンコーディングの誤りがある行は出力されません（メッセージはバイナリファイルのときと同じですが、`-I` のときは出ません）。`-o` は一致だけを見ます。
- 標準入力にある通常のファイルは、GNU grep が残すのと同じ位置に残します。`-m` が検索を終えたときは、最後に選んだ行の直後、そうでなければ最後に読んだ塊の終わりです。
- ディレクトリは、GNU grep の `fts` と同じく、ファイルシステムの順に読みます。fixture やスクリプトが順序に依存するなら `sort` を使ってください。

## `-P`

`-P` を最初に使うとき、システムの PCRE2 ライブラリを `dlopen` で開きます。そのため、ビルドにそのファイルは要らず、ライブラリがなければ失敗するのは `-P` だけです（`grep: Perl matching not supported in a --disable-perl-regexp build`）。結果とエラーメッセージはライブラリのもので、その版に従います。フラグは GNU grep と同じです。`DOLLAR_ENDONLY`、`-i` のための `CASELESS`、UTF-8 ロケールでの `UTF`・`UCP`・`MATCH_INVALID_UTF`、そして `-w` と `-x` のために包んだパターンです。受け付けるパターンは 1 つだけで、これも GNU grep と同じです。

## 速度

`gbench` 式の実行で測りました。100 万行のログ風の行（57 MB）、`C.UTF-8`、1 スレッド、3 回の中央値、同じマシンの GNU grep 3.12 と比べています。比が 1 より小さければ GNU grep より速いことを表します。

| 処理                                    |   GNU grep（秒） |   ripgsed（秒） |    比 |
|---------------------------------------|---------------|--------------|------|
| `ERROR`                               |         0.109 |        0.13  | 1.19 |
| `-c ERROR`                            |         0.066 |        0.068 | 1.04 |
| `-i error`                            |         0.159 |        0.142 | 0.9  |
| `-n ERROR`                            |         0.132 |        0.164 | 1.24 |
| `-E 'user=(alpha|beta).*id=[0-9]{5}'` |         0.23  |        0.446 | 1.94 |
| `-o '[0-9]\+'`                        |         1.506 |        1.038 | 0.69 |
| `-wc alpha`                           |         0.298 |        0.119 | 0.4  |
| `-Fc -e alpha -e beta`                |         0.156 |        0.156 | 1    |
| まれなリテラル                               |         0.072 |        0.052 | 0.72 |
| `-c '\(a\)\1'`（後方参照）                  |         0.638 |        1.529 | 2.4  |
| 日本語テキスト、`-c '\w\+'`                   |         0.367 |        0.07  | 0.19 |

すべての一致が含むリテラルを入力全体から探し（大文字小文字を区別しない場合も）、それを含む行だけを調べます。遅いのは、いくつもの選択肢と繰り返しを持つパターン（エンジンは行ごとに調べますが、GNU grep の DFA はバッファ全体を走査します）と、後方参照です。sed モードの並列実行は、grep モードではまだ使っていません。
