# アーキテクチャ

背景と根拠は [DESIGN.md](DESIGN.md) にあります。本書は現時点の構成と方針の記録であり、確定仕様ではありません。

## 構成

crate は一つ（lib + bin）。依存境界が固まるまで workspace 分割はしません。

| モジュール                | 担当すること                                       | 担当しないこと     |
|----------------------|----------------------------------------------|-------------|
| `syntax`             | トークン化、AST、ソース位置、構文診断（`parser`）               | 実行、ファイル書き込み |
| `regex`              | 正規表現エンジン：BRE/ERE の方言、左端最長一致、キャプチャ            | sed の構文、置換  |
| `runtime`            | サイクル、pattern/hold space、コマンド評価、`s` と `y`、`l` | CLI 引数の解釈   |
| `io`                 | レコードの読み込み、出力ストリーム、`w` ファイル、インプレース編集、標準入力     | スクリプト構文     |
| `debug`              | `--debug` のプログラムの正規形と実行トレース                  | スクリプトの実行    |
| `cli`                | オプション解析、モード決定、終了状態                           | 変換ロジックの別実装  |
| `analysis`           | スクリプトがレコード内で完結する（チャンクごとに独立して実行できる）かを静的に判定する  | スクリプトの実行    |
| `parallel`, `stream` | 順序つきチャンクストリーム、ワーカー、出力の順序つきマージ                | スクリプトの意味    |
| `search`             | バイト・部分文字列検索（SSE2/AVX2、スカラー実装へのフォールバック付き）     | 正規表現        |

## 正規表現エンジン

検索は最大3段階を通ります。後の段階ほど高価で、どの段階も NFA シミュレーションと完全に同じ結果を返します。

1. **リテラル先読み**（`regex::literal`）。リテラルだけのパターンは部分文字列検索で答えます。あるリテラルを必須とするパターン（単純なグループにまたがってもよい）は、それを含まない入力をオートマトンを動かす前に弾きます。
2. **遅延 DFA**（`regex::dfa`）。パターンに後方参照がなく、入力に区切り文字・改行バイトがない（UTF-8 ロケールでは ASCII のみ）ときに使います。前向きの非アンカー DFA が最も早いマッチ終端を見つけ、逆向き DFA（パターンを鏡写しにして構築）がそこで終わるマッチの最左の開始位置を見つけます。それより前の開始位置から始まるマッチは終端がより後ろになるはずなので、前向きのアンカー DFA を作業量の上限内で順に試し、最長の終端も前向きのアンカー DFA が求めます。状態は必要になったときに作ります（最大2000。超えたらフォールバック）。最初に最も早い終端を探すことで、長い1行に対する繰り返し検索も線形時間に収まります。
3. **NFA シミュレーションとバックトラック**（`regex::exec`）。基準となる実装です。後方参照、非 ASCII 入力、DFA が引き受けないものすべてを扱い、DFA が見つけた範囲に対して部分マッチを割り当てます。

DFA 経路は、ランダムなパターンと入力でシミュレーションと突き合わせ（`regex::tests`）、有効にした状態で fixture と実行 fuzz テストも通しています。

## 方針

- CLI と Rust API は同じ経路（パースしてから実行）を共有します。大きな通常ファイルに対するレコード内完結のスクリプトは、順序つきチャンクストリーム上で並列に実行し、それ以外は逐次 VM で実行します。
- 未対応構文はコンパイル時エラーとし、黙って別の意味に解釈しません。
- 入力はバイト列として保持します。レコード末尾の区切りは本文と区別して扱います。

## 由来とライセンス

- GNU sed と GNU grep のソースは、挙動を調べるためだけに `reference/`（git 管理外）に置きます。そこからコードは写しません。
- テストの期待値は GNU sed をコマンドとして実行して生成します（リポジトリの `tests/README.md` を参照）。
- プロジェクトは `MIT OR Apache-2.0` でライセンスされています。このライセンスと衝突するため、GPL のコードに由来するものは追加してはいけません。
