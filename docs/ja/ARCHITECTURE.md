# アーキテクチャ

背景と根拠は [DESIGN.md](DESIGN.md) にあります。本書は現時点の構成と方針の記録であり、確定仕様ではありません。

## 構成

crate は一つ（lib + bin）。依存境界が固まるまで workspace 分割はしません。

| モジュール     | 担当すること                                       | 担当しないこと     |
|-----------|----------------------------------------------|-------------|
| `syntax`  | トークン化、AST、ソース位置、構文診断（`parser`）               | 実行、ファイル書き込み |
| `regex`   | 正規表現エンジン：BRE/ERE の方言、左端最長一致、キャプチャ            | sed の構文、置換  |
| `runtime` | サイクル、pattern/hold space、コマンド評価、`s` と `y`、`l` | CLI 引数の解釈   |
| `io`      | レコードの読み込み、出力ストリーム、`w` ファイル、インプレース編集、標準入力     | スクリプト構文     |
| `debug`   | `--debug` のプログラムの正規形と実行トレース                  | スクリプトの実行    |
| `cli`     | オプション解析、モード決定、終了状態                           | 変換ロジックの別実装  |

`analysis` と `plan`（並列実行）はまだ書いていません。GNU sed の完全互換の後に取り組みます。

## 方針

- 今のところ逐次 VM だけです。CLI と Rust API は同じ経路（パースしてから実行）を使います。
- 未対応構文はコンパイル時エラーとし、黙って別の意味に解釈しません。
- 入力はバイト列として保持します。レコード末尾の区切りは本文と区別して扱います。

## 由来とライセンス

- GNU sed と GNU grep のソースは、挙動を調べるためだけに `reference/`（git 管理外）に置きます。そこからコードは写しません。
- テストの期待値は GNU sed をコマンドとして実行して生成します（リポジトリの `tests/README.md` を参照）。
- プロジェクトは `MIT OR Apache-2.0` でライセンスされています。このライセンスと衝突するため、GPL のコードに由来するものは追加してはいけません。
